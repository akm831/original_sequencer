# 画面の操作を、正確なタイミングで音にする

画面を動かす処理と音を作る処理は別々に動きます。音声処理は一定時間ごとに呼ばれるため、画面から直接音の内部状態を書き換えると、途中の状態を読んでしまう可能性があります。

そこで「何番目の音声Sampleで鳴らすか」を指定した小さな指示を、固定容量の受け渡し箱（Command Queue）に入れます。容量を固定すると、音声処理中に箱を拡張するためのMemory確保を避けられます。満杯の場合は待たずに失敗を返します。

例えば、音声処理がSample 1000〜1095を作るとき、Sample 1037で鳴らす指示があれば、最初の37 Samplesを先に作り、そこで音を開始します。今回のテストは、表示された数値だけでなく、実際の出力にその位置から音があることを調べます。

音声処理のBufferを96 Samplesから別の長さに変えても、同じ時刻から同じ波形が出ることも確認します。音楽のタイミングがDeviceのBuffer Sizeによって変わらないための基礎になります。

今回は動作確認用の短い音です。複数の音を重ねる仕組み、16-stepの繰り返し、楽器としての音作りは、別の段階で追加します。Host testはプログラムの計算を検証でき、実機試験はスマートフォンの音声Deviceや操作遅延を検証します。
